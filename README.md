# Учебная виртуальная машина (УВМ): Ассемблер и Интерпретатор

Реализация однопроходного CLI-ассемблера и интерпретатора для учебной виртуальной машины (УВМ) с аккумуляторной архитектурой. Ассемблер транслирует человекочитаемый код в формате CSV в бинарный машинный код, а интерпретатор выполняет полученный байт-код.

---

## 1. Архитектура УВМ

* **Аккумулятор (`reg`)**: единственный рабочий регистр процессора, через который проходят все операции загрузки, чтения и сравнения. Начальное значение — `0`.
* **Память данных (`mem`)**: линейный массив из 50 ячеек (адреса от `0` до `49`), изначально заполненный нулями.
* **Формат машинной команды**: каждая инструкция имеет фиксированную длину **4 байта (32 бита)** и записывается в порядке **Little-Endian** (от младшего байта к старшему).
* **Битовая структура слова**:
  * Биты `0–2` (3 бита): код операции (`A`).
  * Биты `3–26` (24 бита) или `3–17` (15 бит): операнд/аргумент (`B`). Неиспользуемые старшие биты заполняются нулями.

---

## 2. Язык ассемблера (формат CSV)

Исходный код программы представляет собой текстовый CSV-файл (разделитель — запятая `,`) в кодировке `UTF-8`.

### Правила синтаксиса
1. **Структура строки**: каждая инструкция записывается на новой строке в формате:
   ```csv
   команда,аргумент
   ```
   Для команд без аргументов (`read`) второй столбец оставляется пустым (например, `read,` или просто `read`).
2. **Регистр и пробелы**: названия команд нечувствительны к регистру (`load`, `LOAD` и `Load` эквивалентны). Лишние пробелы по краям ячеек автоматически игнорируются.
3. **Заголовок таблицы**: первая строка файла может содержать шапку (`op,arg`, `command,arg` или `cmd,arg`) — транслятор автоматически её пропустит.
4. **Комментарии и пустые строки**: пустые строки, а также строки, начинающиеся с символа `#`, игнорируются при трансляции.

## 3. Система команд УВМ

| Мнемоника | Опкод (`A`) | Разрядность аргумента (`B`) | Формат в CSV | Описание операции |
| :--- | :---: | :---: | :--- | :--- |
| **`load`** | `0` (`0b000`) | 24 бита (биты `3–26`) | `load,<const>` | Загрузка константы `B` в аккумулятор: `reg = B` |
| **`read`** | `1` (`0b001`) | Нет (0 бит) | `read,` | Чтение из памяти по адресу из аккумулятора: `reg = mem[reg]` |
| **`ge`** | `4` (`0b100`) | 15 бит (биты `3–17`) | `ge,<addr>` | Операция «больше или равно»: `reg = int(reg >= mem[B])` |
| **`write`** | `7` (`0b111`) | 15 бит (биты `3–17`) | `write,<addr>` | Запись значения аккумулятора в память: `mem[B] = reg` |

## 4. Использование (CLI)

### Ассемблер (`uvm-asm.py`)

Синтаксис запуска:
```bash
python uvm-asm.py <путь_к_исходнику.csv> <путь_к_результату.bin> [--test]
```

**Аргументы командной строки:**
* `input` — путь к входному файлу с программой на языке ассемблера (CSV).
* `output` — путь к выходному двоичному файлу (`.bin`).
* `--test` *(опционально)* — включает режим тестирования: выводит на экран промежуточное представление (поля и значения) и сгенерированный машинный код в шестнадцатеричном байтовом формате.

**Пример запуска в режиме тестирования:**
```bash
python uvm-asm.py test.csv uvm-output.bin --test
```

### Интерпретатор (`uvm-interp.py`)

Синтаксис запуска:
```bash
python uvm-interp.py [путь_к_бинарнику.bin]
```

**Аргументы командной строки:**
* `binary` *(опционально)* — путь к бинарному файлу с машинным кодом. Если аргумент не указан, по умолчанию открывается `uvm-output.bin`.

После выполнения всех инструкций интерпретатор выводит в консоль итоговое значение регистра `reg` и состояние массива памяти `mem`.

## 5. Примеры программ

### Тестовая программа из спецификации (`test.csv`)

Проверяет корректность кодирования всех четырёх инструкций:

```csv
# Тестовый набор команд из спецификации УВМ
op,arg
load,1006
read,
write,713
ge,278
```

Результат выполнения `python uvm-asm.py test.csv uvm-output.bin --test`:

```text
Промежуточное представление (поля и значения):
load: A=0, B=1006
read: A=1
write: A=7, B=713
ge: A=4, B=278

Машинный код (байты):
0x70, 0x1F, 0x00, 0x00
0x01, 0x00, 0x00, 0x00
0x4F, 0x16, 0x00, 0x00
0xB4, 0x08, 0x00, 0x00

Размер двоичного файла: 16 bytes
```

### Пример исполняемой программы (`program.csv`)

Записывает число `42` в 5-ю ячейку памяти, загружает число `50` в аккумулятор и проверяет, что `50 >= mem[5]`:

```csv
op,arg
load,42
write,5
load,50
ge,5
```

После трансляции и запуска интерпретатора в аккумуляторе `reg` окажется `1` (истина), а в `mem[5]` будет храниться `42`.
